# SWARMFALL — D02 / OPERATIONS & REPLAYABILITY SPEC

**Редакция:** v0.3 · 22.10.2026 (утверждено владельцем после REVIEW/DECISIONS)  
**Статус:** **`APPROVED DESIGN` — ТОЛЬКО СОЛО, O01–O06 + C-A01.** Шесть `D02-DEC-01…06` утверждены владельцем 22.10.2026; все численные балансовые кандидаты остаются `TUNABLE / UNSIGNED`, тесты — `NOT_RUN`, техническая реализация — `DEFERRED`.  
**Назначение:** производственная предметная спецификация **одиночных** сюжетных операций O01–O06, дополнительного C-A01, условий прохождения, повторов, сюжетного допуска, испытаний и приёмки. **Не команда писать игру.**

## 0. Границы, нормативность и правило чтения

1. `SWARMFALL_D01_COMBAT_GAMEPLAY_SPEC_v0.3.md` — **APPROVED DESIGN** для одиночного боя. D02 не меняет соло-смерть, правило `fatal LOSS > WIN`, однократные убийства, сохранение подтверждённого прогресса, принципы реакторных атак, одинаковую боевую семантику трёх камер и ограниченную вариативность.
2. `SWARMFALL_AUTHORITY_MAP_v0.3.md`, `SWARMFALL_DECISION_LOG_v0.3.md` и `SWARMFALL_D00_APPROVAL_RECORD_v0.3.md` — границы утверждений, в частности кооператив `OPEN`. `SWARMFALL_MASTER_GDD_v1.0.md` — продуктовая опора; `SWARMFALL_PROGRESSION_02_08_CONTRACTS_OPERATIONS_v0.2.md` — главный действующий источник состава и смысла операций.
3. `SWARMFALL_FIRST_RUN_RETENTION_CONCEPT_v0.5.md` (только действующая верхняя поправка), `...02_06_EVOLUTION_RECIPES_v0.2.md`, `...02_07_ECONOMY_v0.3.md` — приоритет в эволюциях, уникальных компонентах и экономике. **Устарело:** 7 обязательных операций, 135 убийств, временный Громовержец в O01, блокировка рельсотрона испытанием точности.
4. `src.7z` — прежний прототип; его конкретные `Maps`, spawn/lua-настройки и координаты не обязательны к повторению. Можно использовать подходящие идеи и код, но будущая миссионная семантика задаётся документацией.
5. Конкретные контракты шести решений `D02-DEC-01…06` утверждены и имеют приоритет над ранее предложенными кандидатами. Остальные обозначения `PROPOSED D02-Rxx`, не охваченные решениями владельца, остаются предложениями, а не разрешением на новые игровые механики.
6. В D02 **нет** правил группового запуска, распределения добычи между игроками, сетевых reconnect-политик и самостоятельного дизайна базы. D04/D05 позже. Сценарии настоящего документа описаны для одного игрока.

- **Утверждены:** `D02-DEC-01…06` в редакции `SWARMFALL_D02_DECISION_PACKAGE_v0.3.md` — разделённые часы задач/финалов, 100% перенос O02, конкретные роли боссов, глобальная лестница угроз, whitelist-повторы, добровольность испытаний.

- **Не утверждено:** HP, DPS, секунды, зарядные единицы/радиусы, пороги фаз, tier-множители, размеры бонусов, сетевые гарантии, кооператив, реализация кода. `APPROVED DESIGN` не равно `BALANCE VERIFIED` или `IMPLEMENTATION COMPLETE`.

### 0.2. Типы данных в документе

- **`LOCKED/CANON`** — уже согласованный смысл, который можно реализовать без перестройки.
- **`PROPOSED`** — будущая деталь вне утверждённых D02-DEC-01…06, не обязательна без отдельного решения.
- **`TUNABLE`** — число или окно, параметр конфигурации с единицами, без окончательного диапазона до плейтеста; агент может выбрать `PROVISIONAL` по DEC-08, фиксируя гипотезу и измерения.
- **`DEFERRED`** — другой документ, не выводить из него неявное решение.

## 1. Каноническая линия кампании

| ID | Операция | Регион | Обязательное боевое действие | Условие первой победы / открытия |
|---|---|---|---|---|
| `O01` | **Первый контакт** | Реакторный двор | Защита реактора, убийство Носителя ядра, последняя волна | O02 + первая технология; Ядро Бури — **за убийство элиты**, даже если финал проигран |
| `O02` | **Клещи периметра** | Реакторный двор | Заряд внешнего ретранслятора убийствами рядом, защита реактора, последний натиск | O03 + чертёж Вулкана + доступ к C-A01 |
| `O03` | **Гнездовой прорыв** | Реакторный двор | Уничтожить **2 из 3** гнёзд, защитить реактор и завершить волну | O04 + чертёж Разлома |
| `O04` | **Матка Разлома** | Реакторный двор | Защита реактора + смерть Матки | O05 + Глубины улья + чертёж рельсотрона |
| `O05` | **Цепная реакция** | Глубины улья | Уничтожить оба питающих узла, защитить сердцевину, завершить волну | O06 + компонент будущей Адской мельницы |
| `O06` | **Сердце глубин** | Глубины улья | Защита сердцевины + смерть Пожирателя | Состояние «глава завершена», продвинутые повторы, компонент будущего Копья Пустоты |
| `C-A01` | **Кислотный фронт** | Реакторный двор | Уничтожить 2 кислотных источника, защитить реактор, закончить волну | Необязательный контракт, награды и исследования; **не** переход по кампании |

`CANON`: новые сюжетные миссии O01…O06 открываются **первой победой предыдущей операции на T1 или выше**; C-A01 — после O02. Выбор T2–T5 не является условием продолжения сюжета. Впервые открываемая операция по умолчанию T1. До первой победы O01 новичок может повторять O01; первое соло-знакомство происходит сразу в бою, без обязательной прогулки по хабу.

### 1.1. Одна карта — несколько разных задач

- O01/O02/O03/O04 используют **один регион** с разными объективными механиками: простой реактор, внешний ретранслятор, уничтожение гнёзд, босс. Это не четыре визуально идентичные волны под разными названиями.
- O05/O06 используют **Глубины улья**; O05 обучает обращать взрывы против узлов, O06 завершает главу боссом.
- Изменение основной цели между операциями обязательно. Возможность пройти любую обязательную сюжетную операцию стартовой винтовкой и на T1 должна сохраняться; нельзя запереть O03 за купленным Разломом, O04 за рельсотроном, O05 за Вулканом или O06 за условием точности.

## 2. Единый контракт `MissionInstance` / `MissionObjective` (обязательная семантика D02; кодовая структура — D06)

**Модель данных (смысл, не Luau-структура):**

```text
MissionDefinition {
  missionId; mapId; kind: STORY|OPTIONAL; minUnlockFlag;
  objectiveAnchorType: REACTOR|HIVE_CORE;
  permittedEnemySpecies; permittedEliteAndBossIds;
  requiredObjectives[]; optionalObjectives[];
  eventTimeline[]; deadlinePolicy; victoryPredicate; failurePredicate;
  firstClearEntitlements[]; repeatRewardPolicy;
  allowedReplayVariants[]; threatProfileRef; introRules;
}
MissionInstance {
  runId; missionId; threatTier; isFirstStoryAttempt; isFirstClearCandidate;
  missionSeed; runtimePhase; objectiveStates{}; anchorState;
  eventFiredIds{}; confirmedKillIds{}; confirmedUniqueGrantKeys{};
  spawnedBossIds{}; sessionStartTime; activeCombatTime;
  ending: NONE|WIN|LOSS; resultCommitKey;
}
```

Это перечень **необходимых смысловых полей**, не пожелание конкретного файлового формата. Конкретное хранение persistent флагов — D03/D04.

### 2.1. Общий порядок событий и исходов

1. До старта проверить **допуск к операции**, выбранную угрозу и базовое вооружение. Нельзя выдать скрытый бесплатный недоступный предмет ради прохождения.
2. При старте запомнить версию `MissionDefinition` и seed; активный счётчик **останавливается** во время утверждённой соло-паузы карточек/первого S01, если часы сценария основаны на active combat time. Сетевая загрузка не расходует боевое время.
3. `SpawnEnemy`, `EnemyKilled`, `ObjectiveDamaged`, `ObjectiveDestroyed`, `BossKilled`, `PhaseElapsed`, `MissionDeadlineReached` обрабатываются **идемпотентно**, с уникальным ключом события в рамках `runId`. Босс не создаёт второе убийство поверх обычного `KillEvent`.
4. За один авторитетный шаг сначала фиксируются валидные убийства/уникальные компоненты/прогресс целей, затем проверяется D01 `LOSS > WIN` и публикуется **ровно один** терминальный результат. Никакого клиентского самостоятельного определения победы.
5. `WIN` выдаёт сюжетное открытие и first-clear только один раз по устойчивому ключу `playerId + missionId + entitlementId`; `LOSS` не выдаёт first-clear, но не отнимает подтверждённые убийства/исследования, честные компоненты и Ксенит согласно D03/D04.
6. `Deadline`: в момент **объявленного терминального лимита** завершить попытку ровно один раз. Порядок в пределах шага: (а) подтверждение допустимых хитов/убийств/целей, (б) проверка смерти героя и защищаемого объекта → `LOSS`, (в) проверка полной победы → `WIN`, (г) проверка истечения доступного лимита при невыполненной победе → `LOSS`, (д) иначе продолжение. Если победная цель достигнута **в том же шаге**, что истёк лимит, но фатального события нет, засчитывается `WIN`. Подтверждённые убийства и kill-entitlements не аннулируются. **Для небоссовых операций используются раздельные публичные часы**: дедлайн обязательного действия, финальная фаза и общий cap, по D02-DEC-01; численные длительности ещё TUNABLE. Не преобразовать softlock/ошибку спавна босса в «честный проигрыш» без отдельной технической политики D04/D06.
7. Непонятный результат/дублирующиеся сетевые события не дают дополнительных наград. Правила аварийной записи и disconnect — **DEFERRED D04**, а не «авто-поражение без награды».

### 2.2. Универсальные состояния цели

`UNAVAILABLE → REVEALED → ACTIVE → COMPLETED` либо `ACTIVE → FAILED` (для разрушаемых обязательных узлов допускается `DAMAGED → DESTROYED` как подстатус); завершение необратимо в рамках попытки. **Не допускается** выполнить цель до её допустимой активации за счёт случайного AoE, прогрузки/невидимой геометрии либо повторно получить бонус за один объект. Если игрок реально может заранее стрелять по видимому объекту, его доступность и зачёт должны быть согласованы; нельзя отображать уязвимый объект и игнорировать урон без объяснения.

### 2.3. Контракт защищаемого объекта — наследование D01

- На всех 7 операциях указанный `ObjectiveAnchor` действительно уязвим и находится на уровне; HP≤0 является фатальным `LOSS`.
- Только достижимые, видимые, телеграфированные при серьёзной угрозе нападения разрешают урон; игрок не должен погибать из-за нападения через стену/за границей карты.
- На вылазках O02/O03/O05/C-A01 игрок обязан иметь реальное время отреагировать на натиск по защищаемой цели; **запрещена** механика, где главный объект обречён, пока игрок честно выполняет обязательную далёкую задачу.
- «Сердцевина» O05/O06 — тематическая разновидность `ObjectiveAnchor`; в рамках D02 не получает скрытых уникальных валют, механики ручного ремонта или неутверждённого восстановления HP. Новые атаки боссов, способные повредить цель, подчиняются обычной геометрии и телеграфам D01.

## 3. Завершение небоссовых операций — D02-DEC-01 APPROVED DESIGN

`O01`, `O02`, `O03`, `O05`, `C-A01` требуют **выполненную боевую задачу + отдельную завершающую фазу** при живых герое и защищаемом объекте. Нельзя ни мгновенно побеждать после промежуточной задачи, ни ждать последнего застрявшего NPC. Это **утверждённое правило D02**, согласованное с D01.

### 3.1. Три различных момента, которые нельзя называть одним таймером

- **`objectiveDeadline`** — объявленный игроку предел времени на обязательное действие (O01: убить Носителя; O02: зарядить катушку; O03: 2 гнезда; O05: 2 узла; C-A01: 2 источника). Не может незаметно наступать раньше разумной возможности выполнить задачу.
- **`finalPressureDuration / finalResolveWindow`** — необходимое активное боевое время после выполнения основной цели, сопровождаемое реальными угрозами. В O01 начинается строго после подтверждённой смерти элиты; не подменяется сценой награждения. Никаких дополнительных типов врагов.
- **`absoluteTerminalCap`** — **публичный верхний предел** всей попытки, выбранный так, чтобы законное выполнение цели вплоть до `objectiveDeadline` оставляло место на обязательную финальную фазу. Инвариант: `absoluteTerminalCap >= objectiveDeadline + finalPressureDuration + finalResolveWindow` с учётом точной семантики пауз. Численные значения — `TUNABLE / NOT SIGNED`, UX-подача — D05; само разделение часов утверждено.

**Обязательное поведение:** финальную фазу запускать **после** подтверждённого выполнения обязательной цели, с минимальной запланированной интенсивностью; засчитывать конец после выполненного выпуска и короткого `resolveWindow`, когда ещё живые, реально угрожающие объекту группы не создают недостижимый блокер. Не допускается мгновенно завершать сценарий только потому, что достигнут лимит активных NPC или нагрузочный бюджет; нельзя наградить игрока за «финал», который не состоялся из-за оптимизации.

### 3.2. Застрявшие NPC и реальная угроза

- Никакой «убей вообще последнего врага на карте»: потерянный путь/ошибка геометрии одного NPC не блокирует победу. Устранение такого NPC **не считается боевым убийством** и не даёт XP/мастерства.
- Если в момент планового окончания всё ещё идёт явная атака по реактору, переход к победе допускается **только после правилом определённого разрешающего окна** с честным учётом уже нанесённых атак и `fatal > win`; нельзя показать WIN, проигнорировав зарегистрированное в том же шаге разрушение реактора.
- Если нагрузочное ограничение не позволяет вывести заявленную интенсивность, уменьшить профиль эффектов/частоту анимации/настроенный спавн при сохранении игрового смысла, зафиксировать отклонение на плейтесте; **не объявлять** невыпущенную волну выполненной.
- Повторная фаза выбирается по `missionId`, `seed`, версии сценария и только разрешённой вариативности; первая O01 — фиксированная постановка.

### 3.3. Защита от поздней цели и бесконечного боя

- При невыполненной цели показывать `objectiveDeadline`; при истечении — `LOSS` без возникновения финальной фазы. **Дедлайн не появляется после успешного достижения цели задним числом.**
- При достижении цели в последнем допустимом шаге запускается полная обещанная финальная фаза, а не урезанная до нуля. Поэтому `absoluteTerminalCap` обязан включать её максимальную длительность. Продление не бесконечно и показывается игроку.
- В O04/O06 отдельной финальной фазы после босса **нет**: подтверждённое убийство босса + живые герой/объект → `WIN` немедленно по принятому D01 правилу конкурирующих событий.

**Объективная проверка:** моделировать цели, выполненные рано, в середине, за один шаг до `objectiveDeadline`, ровно в этот шаг и после него. Разработчик не назначает сроки произвольно; все таймеры должны пройти совместную проверку достижимости стартовым оружием на T1.

## 4. O01 — «Первый контакт»: контракт первой попытки

**CANON:** `MAP_REACTOR_YARD`, `EN_RUNNER` + `EN_SPITTER` (2 обычных вида), одна **уникальная** элита `ELITE_CORE_CARRIER` ближе к концу. Нет `EN_STALKER`, `EN_BULWARK`, `EN_BOMBER`, Матки, Пожирателя, дополнительных элит, ретрансляторов, обязательных гнёзд, иных противников даже в повторном O01. Старт W01 Arc Rifle, XP-предметы и карточки, в первой попытке — обучающее самостоятельное использование S01 Гравимолота.

### 4.2. Первая элита и уникальный компонент

- `ELITE_CORE_CARRIER` имеет **одну** подтверждённую смерть на попытку. От неё выдаётся одна постоянная `StormCore`-зацепка для будущего Громовержца (название «Ядро Бури»), **не активируется** форма оружия, не создаётся дополнительный базовый навык.
- Подтверждённое убийство элиты даёт предмет даже при `LOSS` в ту же боевую границу. Повторная попытка не дублирует единовременный сюжетный компонент (ключ владения — D03/D04).
- Смерть элиты **не** завершает операцию: после неё финальный натиск и только затем `WIN` при оставшемся живом реакторе и герое.
- First-clear O01 выдаёт O02 и право просмотреть две стартовые технологии. Одноразовый грант до 180 Ксенита — **экономическое правило D03/02.7, не награда за отдельный KillEvent и не автоматическое бесплатное изготовление**.

### 4.3. Критичные крайние случаи

- Элита гибнет в тот же шаг, что реактор/персонаж → `LOSS`, компонент/килл остаются.
- Элита ещё жива к плановому времени роя → рой **не стартует и не засчитывается**; активен **видимый срок на добивание элиты** (`objectiveDeadline`). Если она убита в последнем допустимом шаге, запускается полноценный финальный рой, не урезанный старым лимитом. `absoluteTerminalCap` рассчитывается по §3; числа и UX-подача остаются TUNABLE/D05, **разделение фаз утверждено**.
- Игрок не сумел подобрать сферу опыта → S01 и финальные события не должны зависеть от обязательной карточки.
- При повторах не показывать обязательную обучающую паузу уже открытого S01; рефреш доступности навыка соответствует выбранной экипировке.

## 5. O02 — «Клещи периметра»: внешний ретранслятор

**CANON:** впервые вводится `EN_STALKER` (Прыгун/Охотник), бой смещается к внешней энергетической катушке/ретранслятору. Она заряжается **уничтожением врагов в зоне**, а не неподвижным ожиданием или удержанием кнопки. Реактор остаётся защищаемой целью.

### 5.1. Состояния и прогресс цели (D02-DEC-02 APPROVED DESIGN)

`RELAY_INACTIVE → RELAY_ACTIVE → RELAY_CHARGED`; при разрушении/невозможности использовать основную — `RELAY_DISABLED → RELAY_BACKUP_ACTIVE`; при окончательной утрате обеих катушек `FAILED`.

- Успешное `KillEvent` проверяет позицию **погибшего врага** в момент подтверждённой смерти; если внутри зоны активной катушки и `missionPhase` разрешает заряд, начисляет `relayCharge` **ровно один раз** по тому же `enemyId`. Позиция игрока сама по себе не влияет на заряд; не нужно стоять в круге без стрельбы.
- Пробный баланс 60 единиц, радиус ~30 studs, Бегун +1, Плевун +2, Прыгун +3 — `TUNABLE`, не новые кошельки и не мастерство. Убийства от S01/оружия учитываются согласно общему Damage/Kill контракту и могут заряжать катушку, не создавая ещё одного оружейного убийства.
- Заряд на катушке не обнуляется при обычной атаке и не уменьшается сам по себе. `CHARGED` не может стать `UNCHARGED` после достижения условия. Перегрузка и повреждение катушки отличаются от потери миссионного прогресса.
- При потере основной катушки **до** `RELAY_CHARGED` активируется ровно одна доступная запасная с переносом **100% подтверждённого накопленного заряда** (общий накопитель; без округления, списания или дублирования; например 37/60 → 37/60 — цифры лишь иллюстрация). Если обе окончательно недоступны **до** заряда, → явное `LOSS`. После `RELAY_CHARGED` цель закрыта необратимо: повреждение/разрушение катушек не отменяет выполненный заряд и не даёт нового `LOSS` за уже выполненную стадию. Резерв нельзя активировать в недостижимой позиции или включить без явного предупреждения. Всё это **утверждено `D02-DEC-02`**.
- Игрок должен иметь возможность выполнить цель до явного финального дедлайна, даже если не успел к ориентировочному 5:30.
- Прогресс при поражении миссии не сохраняется как отдельная вечная валюта (в отличие от личных убийств/исследований/Ксенита).
- **Кто повреждает катушку:** только физически находящиеся рядом и способные выполнить читаемую атаку **уже разрешённые враги** в рамках миссионной роли. Нет мгновенного «сценарного выключения» катушки вне поля восприятия. Атака по катушке и реактору не может создать заведомо неразрешимый двойной дедлайн. Самонаводящийся урон через препятствие запрещён. Правила допустимых целей врага — часть утверждённого `D02-DEC-02`, значения HP — TUNABLE.
- **Заряд и геометрия:** учитывать убийство врага по моменту летальной смерти, а не по более раннему hit или последующему отбрасыванию трупа. Счётчик работает только для **активной** катушки; местоположение спавна и потоки должны позволять реалистично убивать в зоне, а не вынуждать стоять в ней и ждать. Заряд не начисляется за despawn, контакт с ловушкой без подтверждённого KillEvent или повторный event.

| `CORE_PRESSURE` | Босс может начать явно обозначенную атаку на энергетическую сердцевину с реальным окном перехвата | Запрещён гарантированный урон по объекту без доступного противодействия |

`ENTER → PHASE_A → SHIFT → PHASE_B → DYING`, переходы по HP/событию как TUNABLE. Boss HP/слабые зоны/сопротивления **не** финальны, но любая атака имеет telegraph, истинную геометрию поражения и recover. В финале игрок должен использовать навыки, которым научился ранее, а не осваивать внезапную новую валюту.

**D02-DEC-03 APPROVED DESIGN / boss viability:** правило минимально достижимого окна и технического spawn-fail-safe из O04 действует и здесь. `CORE_PRESSURE` не может выбирать невидимую точку поражения и убивать сердцевину во время обязательного неинтерактивного входа босса. Реальная реакция должна быть доступна из позиции игрока, разумно занятого боем. Стартовое оружие W01 должно иметь ненулевую и тестируемую возможность выиграть T1 даже без атак в слабую зону.

**`WIN`:** `devourerKilled && coreAlive && playerAlive`; `LOSS`: фатальные события / дедлайн до смерти босса. **First-clear:** `CHAPTER_01_COMPLETE`, открытие продвинутых повторов, один тематический компонент будущего Копья Пустоты. Вторая валюта не создаётся. Нельзя требовать рельсотрон или 3 точных попадания.

## 10. C-A01 — «Кислотный фронт»: необязательный контракт

**CANON:** открывается после O02, не блокирует продвижение по O03–O06. На Реакторном дворе, акцент на Бегунах/Плевунах и заметных кислотных опасностях; **два источника** можно уничтожить прямым уроном.

| Фаза | Ориентир |
|---|---|
| Усиленное знакомство с Плевунами | 0–1:30 |
| Два кислотных источника | 1:30–4:30 |
| Завершающая защита периметра | 4:30–7:30 |

**Обязательный контракт источников кислоты (D02 v0.3):** при уничтожении каждый источник перестаёт создавать **новые** опасные зоны (уже выпущенная кислота доживает свою читаемую длительность). Источники постоянно обозначены после открытия, уязвимы прямой стрельбой с возможностью укрыться от Плевунов; уничтожение обоих не отключает кислые атаки оставшихся Плевунов. Нельзя добавить третий обязательный генератор без изменения сюжета. Никакое добровольное достижение не лишает игрока обычного Ксенита за победу.

**`WIN`:** `destroyedAcidSources==2 && finalWaveCompleted && reactorAlive && playerAlive`. **`LOSS`:** смерть героя/реактора/лимит. **Награда:** обычный Ксенит, исследования, убийства; достижение «Кислотная дисциплина» (не более двух валидных попаданий кислотой) — *пример необязательного испытания*, **не новое условие сюжетной победы**. Контракт не требуется для O03/O04 и не может быть единственным доступным способом поднять исследование Плевуна до порога Разлома.

**Production scope:** если C-A01 не входит в ближайший контрольный срез, он остаётся в первой главе как опциональный backlog, но нельзя удалять его из GDD или объявлять обязательным ради фарма.

## 11. Повторы, выбор угрозы и ограниченная вариативность

### 11.1. Нормативные инварианты

1. Любую **открытую** O01–O06 можно повторять; C-A01 — после O02. Игрок не теряет сюжетные открытия от поражения.
2. Миссия на повторе всегда сохраняет **главную цель, регион, набор допустимых рядовых видов, уникального сюжетного босса**, ограничения O01 и запрет обходить обязательные условия.
3. В первой сюжетной попытке конкретной миссии применяется управляемый обучающий сценарий; **повтор** допускает малые изменения боевой обстановки внутри тех же механик, как утверждено D01-R04.
4. T1–T5 — добровольная отдельная сложность; T1 доступна на всех открытых сюжетных этапах, повышение сложности не открывает тайно O05 раньше O04 и не даёт обязательных уникальных компонентов, недоступных на T1.
5. После D01-туториала повтор O01 не заставляет повторно нажимать учебную паузу S01, если навык навсегда изучен. Впервые встретивший ещё не освоенный S01 игрок всё ещё должен получить шанс изучить его.
6. Независимые карточные предложения сохраняют обычную рандомизацию; повторная вариативность миссии **не подменяет** карточную систему и не гарантирует заранее нужную сборку.

### 11.2. Белый список вариантов (D02-DEC-05 APPROVED DESIGN)

| Миссия | Изменять на повторах можно | Нельзя |
|---|---|---|
| O01 | сторона большей массы Бегунов, допустимые геометрией подходы | дополнительные виды, элиты, раннюю Матку, фазу S01 в другом месте так, что новичок её пропустит |
| O02 | какая катушка используется сначала; направление групп Прыгунов | количество обязательных заряженных катушек, невидимый радиус заряда |
| O03 | охраняемое Броненосцем гнездо, очередность атак с доступных направлений | требовать 3/3, спрятать два гнезда в недоступной геометрии |
| O04 | порядок второстепенных натисков, безопасные направления обычных волн | заменять Матку или пропускать все её телеграфы |
| O05 | порядок приоритетной атаки на узлы, направления подхода Взрывунов | заставлять уничтожать узлы только взрывами |
| O06 | порядок групп известных угроз, второстепенные натиски | заменять финального Пожирателя случайной элитой |
| C-A01 | видимые сектора появления кислоты/Плевунов | невидимые кислотные зоны, третья обязательная цель |

**Утверждённый алгоритмический принцип:** выбрана миссия+угроза+seed+версия контента, затем **одно-два** небольших изменения из разрешённого списка. Контроль противопоказанных сочетаний: не создавать одновременные недоступные задачи, не блокировать все пути возврата, не требовать дополнительных врагов сверх разрешённого ростера. Для отладки повтор с тем же seed и версией контента восстанавливает план событий, но не обязан воспроизводить человеческие действия/все физические состояния.

### 11.3. T1–T5 (TUNABLE; не копировать значения прототипа)

- Пять названных уровней сложности, добровольная повышенная угроза. На новом сюжетном этапе по умолчанию **T1**.
- Различия через регулируемые параметры HP/урона/роли волн, не через запрет известных действий, скрытую «оплату входа» или неуязвимость рядовых монстров.
- В старом коде есть числовые коэффициенты роста по T. Это **не подписанный баланс**; техническая реализация должна брать значения из отдельной версии настроек и измерять TTK/FPS, win rate и нагрузку. Конкретные таблицы — D03/D07 после playtest.
- **Утверждено `D02-DEC-04`: глобальный последовательный допуск.** Первая победа `O01 T1` открывает T2 для всех открытых операций; победа на T2 любой уже доступной операции открывает глобально T3, на T3 → T4, на T4 → T5. Новая операция/регион наследует все уже открытые T. Поражения не открывают и не отнимают уровни. Сюжет можно полностью пройти на T1. Уровни не требуют регионального ресета, покупки или обязательных повторов для сюжетного продвижения. Профильный ключ `highestUnlockedThreatTier`; сохранение D04, числовые коэффициенты D03.

### 11.4. Опциональные испытания без новых валют

- O02: сохранить основную катушку.
- O03: уничтожить 3/3 гнёзд.
- O04: три попадания в слабую зону Матки, **если слабая зона в итоге будет утверждена**.
- C-A01: не более двух валидных кислотных попаданий.

**Утверждено `D02-DEC-06`:** все дополнительные испытания добровольны и не блокируют T1, сюжет, базовые пушки, исследования или основные источники Ксенита. **Ещё не утверждены:** конкретные награды, дополнительные счётчики и календарь; D03 решает экономику, дополнительные функции требуют отдельного решения.

## 12. Награды, прогресс и границы других документов

**APPROVED DESIGN v0.3 — строго различать три триггера:** `KILL_EARNED` (событие убийства: оружейная/видовая атрибуция и Ядро Бури O01), `FIRST_WIN_EARNED` (O02–O06 открытия и компоненты O05/O06) и `OPTIONAL_COMPLETED` (только добровольный бонус). Поэтому смерть Пожирателя в одном шаге с разрушением сердцевины даёт подтверждённое убийство, но **не** `CHAPTER_01_COMPLETE` и не first-clear-компонент O06. Аналогично компонент O05 выдаётся исключительно за первую победу, не за разрушение второго узла, если после него случилось поражение. Награды за проигрыш остаются по D01 и D03, техническая сохранность — D04. Ни одна сторона не выводит `WIN` из факта получения kill-трофея.


| Событие | Что происходит | Кто устанавливает окончательное правило |
|---|---|---|
| Один подтверждённый `KillEvent` | Один источник смерти, видовой счётчик; оружейный мастерство по фактическому оружию/S01 | D01+ D03 для persistent учёта |
| Смерть уникальной элиты O01 | Одно Ядро Бури, даже при поражении после события | D02 канон + D03/D04 commit |
| Первая победа O01 | O02 + доступ к стартовой лаборатории/технологиям; грант при нехватке Ксенита | D02 цель; D03 экономика и сохранение |
| Первая победа O02 | O03 + чертёж Вулкана + C-A01 | D02 цель; D03 сохранение |
| Первая победа O03 | O04 + чертёж Разлома; исследование Плевуна отдельно | D02 цель; D03 исследование/изготовление |
| Первая победа O04 | O05/второй регион + чертёж рельсотрона | D02 цель; D03 entitlement |
| Первая победа O05 | O06 + уникальный компонент для Адской мельницы | D02 цель; D03 entitlement |
| Первая победа O06 | `CHAPTER_01_COMPLETE` + будущие испытания + компонент Копья Пустоты | D02 цель; D03 entitlement |
| Повторная победа | Общий Ксенит/оружейные убийства/исследования, не повторять first-clear предмет | D03 балансовая формула, D04 commit; кооп за пределами |
| Поражение | Не присваивает победное открытие; сохраняет честный подтверждённый прогресс | D01 locked, D03/D04 механика сохранения |
| Опциональные гнёзда 3/3 | Не более одного бонуса +20 до множителей по формуле-кандидату | D03/02.7 |

**Определённые различия:** `unlocked blueprint` ≠ `crafted/owned weapon` ≠ `equipped weapon`; `chapter complete` ≠ автоматический доступ к максимальной угрозе; `first-clear component` ≠ повторная добыча расходуемой второй валюты; временная карта ≠ ключ постоянной эволюции. Эти различия обязательны для любого будущего UI и persistent state.

## 13. Инструментальная наблюдаемость и проверка в игре

Рекомендованные названия событий, не зафиксированные API:

**Критерии для будущего агента:**

- Повторная миссия остаётся узнаваемой, не разрушает сюжетный замысел.
