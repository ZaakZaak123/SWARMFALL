# SWARMFALL — [DESIGN] PROGRESSION 02.9 — LAB / RESULTS UX / REVIEW

**Редакция:** v0.2 REVIEW · **Дата:** 22 октября 2026 г.  
**Статус:** согласованное целевое направление UX после критического ревью; **не финальный графический макет, не задача на реализацию**.  
**Применение:** результаты боя → понятная личная награда/прогресс → необязательное развитие → выбор/подтверждение следующей операции. Компьютер, телефон, геймпад, состояния кооператива и профилей.  
**Приоритет:** v0.2 заменяет положения UX из v0.1, где явно сказано иное. **Полный исходный v0.1 сохранён без изменений отдельным документом.** Остальные подсистемы 02.1–02.8 не пересматриваются.

## 0. Критические результаты REVIEW

**Сильная сторона v0.1:** корректно разделены постоянное/временное, доступность/изготовление/установка, сохранение прогресса после поражения, связь результатов и следующей цели. Фактический UI текущей сборки (`src/client/Menus.luau`) уже имеет две основные вкладки, 3D-превью, мастерскую, экран итогов и кооп-состояния — **его визуальный язык не выбрасываем**.

| Выявленная проблема | Исправленное решение | Причина |
|---|---|---|
| 4 равноправных лобби-раздела: Операции, Арсенал, Лаборатория, Бестиарий | **2 главных пути: «В БОЙ» и «РАЗВИТИЕ»**; внутри Развития контекстные «Арсенал / Лаборатория / Исследования» | Небольшое количество корневых решений, особенно на телефоне; сохраняем все функции |
| Лаборатория дублирует инвентарь и управление модулями в Арсенале | **Арсенал конфигурирует/экипирует**, **Лаборатория только изготавливает/покупает**, **Исследования показывают достигнутые открытия** | Одна ответственность и одна CTA для каждого действия |
| В первой победе одновременно показаны 7+ прогрессов | 3 основных сигнала: **победа + доход; главная личная прибавка; что открылось**. Остальное «Подробнее» | Игрок знает, зачем вернуться, без бухгалтерии |
| «Продолжить» могло выглядеть как немедленный запуск O02 | Переход **на экран В БОЙ с уже выбранной O02**, не автозапуск | Выбор экипировки, угрозы и готовности остаётся сознательным |
| Слишком много экранов для первого изготовления | На первой победе лишь **одна рекомендация-пара из 2 технологий**, вход в неё необязателен; остальные покупки доступны в каталоге | Не скрывать реально открытые M2-модули, но не навязывать объяснение всего каталога |
| Фиксированные холсты 1280×720/1040×660 и масштабирование | На мобиле адаптивная **перекомпоновка по доступной области**, закреплённая CTA в safe area, остальные детали прокручиваются | Уменьшение целого холста создаёт нечитаемые цели нажатия |
| Не определено, что делать, когда результат и профиль приходят в разном порядке | Независимые блоки состояния: подтверждённый итог / награда рассчитывается / подтверждённая награда / ошибка, без ложных нулей | Игрок не должен видеть «денег нет» из-за задержки |
| Кооператив: результат → лаборатория в общей сессии не спроектирован | **Сохраняем текущий безопасный переход в лобби/готовность**; личное развитие не блокирует отряд; подробный выход из боя — отдельная кооп-проверка | Не обещать неподтверждённое поведение сервера |

### Неизменные междокументные решения

- **O01:** только Бегун и Плевун из рядовых, одна финальная элита «Носитель ядра», плотная орда; открывается полезный самостоятельный S01. После боя Ядро Бури — один сюжетный компонент, **не мгновенная рабочая эволюция**.
- **O01→O02→O03→O04→O05→O06** и необязательный C-A01 после O02; второй регион после первой победы над Маткой в O04.
- **Временные 12 карточек × I–III**, XP-сферы, шесть семейств в сборке и их синергии — строго внутри забега. Карточки **не ключи постоянных эволюций**.
- **Мастерство каждого оружия M1–M20:** убийство получает только источник смертельного удара; детализация по видам; Гравимолот имеет независимый счётчик. Один и тот же побеждённый враг учитывается в общем бестиарии, но не раздаётся по нескольким пушкам.
- **Ксенит** — рабочее UI-название одной постоянной валюты, внутренняя `scrap` в legacy-коде остаётся до отдельной миграции. Цены из 02.7 v0.3 — **кандидаты**, не пересчитываем их здесь.
- Модули, постоянные формы и изготовление **не требуют повторного сбора 2 карт и ядра в каждом забеге**. Эволюции выбираются **до запуска**.
- Уже принадлежащие старым профилям оружия/перки не отбирать ради новой сюжетной прогрессии.

## 1. Новая информационная архитектура

### 1.1. Два главных действия в лобби

```text
ЛОББИ SWARMFALL
├─ В БОЙ [главная вкладка, открыта по умолчанию]
│  ├─ СЛЕДУЮЩИЙ КОНТРАКТ — крупная приоритетная карточка
│  ├─ ВЫБОР ОПЕРАЦИИ — O01…O06 / C-A01 / уже пройденные
│  ├─ УГРОЗА — T1…T5 (только законно доступная)
│  ├─ СНАРЯЖЕНИЕ — короткое резюме + «Изменить» → Развитие/Арсенал
│  ├─ СОСТАВ ОТРЯДА / ГОТОВНОСТЬ
│  └─ [В БОЙ] / [ГОТОВ]
└─ РАЗВИТИЕ [вторая главная вкладка]
   ├─ АРСЕНАЛ — оружие, мастерство, выбранная форма, CORE и ADAPTER
   ├─ ЛАБОРАТОРИЯ — изготовление открытого, стартовые технологии, PvE-статы, перки
   └─ ИССЛЕДОВАНИЯ — бестиарий, исследования видов, ближайшие технологии
```

Четыре **понятийные подсистемы** из v0.1 сохраняются, но не являются четырьмя равными кнопками на первом экране. В первую очередь лобби отвечает на вопрос **«Во что сыграю дальше?»**. «Развитие» — единственная точка для покупок, изучения и настройки.

**Первый визит:** активная «В БОЙ», справа/ниже одна доступная следующая операция. Вкладка «РАЗВИТИЕ» может иметь небольшой индикатор новой технологии, но не обязательное модальное обучение. **Старый таб `МАСТЕРСКАЯ`** при будущей доработке логично превращается в `РАЗВИТИЕ`; название физических мест не обязано совпадать с технической навигацией.

### 1.2. Отношение трёх подэкранов развития

**Арсенал = чем я иду воевать?** Просмотр 4 текущих пушек, M-ранг, убийства по видам, текущая форма, выбор одного CORE и одного совместимого ADAPTER, выбрать перед операцией. Если предмет не изготовлен — CTA `ИЗГОТОВИТЬ В ЛАБОРАТОРИИ` **ведёт к конкретному предмету**, а не к общему списку.

**Лаборатория = что могу создать или улучшить?** Контекстный список `Рекомендуется / Доступно / Всё` с фильтрами `Оружие · Боец · Исследования · Навыки (по мере открытия)`. После подтверждённого изготовления — возврат к досье с возможностью установить, либо `УСТАНОВИТЬ` доступно прямо в контекстной карточке без дублированной покупки. Каталог модулей не должен вторично выступать местом сохранения и сравнения всего оружейного билда.

**Исследования = кого изучил и что это открыло?** Вид, общие уничтожения, ближайшая исследовательская награда, где встречается. Если технология доступна к изготовлению — **deeplink на конкретную лабораторную карточку**. Невстреченных существ не раскрывать по имени заранее; элитный сюжетный трофей не выдавать за самостоятельный массовый вид.

### 1.3. Сохранение контекста при перемещении

- Из O02 → `Изменить оружие` → Арсенал → `Вернуться к O02`: **сохраняются выбранные O02, угроза и экипировка**.
- Из результата `Новая технология` → карточка лаборатории → `Назад`: возвращаем к **осмысленному исходному контексту**, а не к первому пункту магазина.
- Из Исследований → изготовление «Кислотного фильтра» → `Назад`: возвращаем в деталь Плевуна.
- Из результатов при первом прохождении `Продолжить` → O02 → `В бой`: пользователь подтверждает запуск один раз уже после проверки снаряжения.
- На телефоне и с геймпада «Назад» всегда имеет очевидный маршрут, не стирающий выбранные предметы.

## 2. Экран результатов — максимально быстрый, но с содержанием

### 2.1. Один экран вместо цепочки наград

**На первом экране** (без скролла на типовом горизонтальном мобильном viewport):

1. Победа/поражение и имя операции; ясная эмоция, короткая анимация, кнопки появляются сразу.
2. `Уничтожено N` (**личный показатель** для коопа, командный отдельно) и `Получено ◈ N Ксенита`. При необходимости `Баланс после: ◈ N` в раскрытии/на карточке покупки, чтобы не путать награду за матч с кошельком.
3. **Один главный факт о постоянном прогрессе:** ранг любимой пушки повышен / следующий модуль близко / сохранены убийства, если проигрыш.
4. **Одно сюжетное открытие**, если произошло: `Открыта O02`, `Чертёж Вулкана`, `Новая карта: Глубины улья`; дополнительные открытия — строка `Ещё 2 открытия`.
5. Две ясные CTA: **основная `ПРОДОЛЖИТЬ → O02`** / `ПОВТОРИТЬ O01` при поражении и вторичная `УЛУЧШИТЬ` либо `ПОДРОБНЕЕ`. Детальный прогресс не обязан умещаться целиком.

**НЕ на первом взгляде:** все три источника 40 видов статистики, полный бестиарий, 12 карт, 20 рангов, большая 3D-модель, все умения, длинная реклама следующего чертежа. Всё это доступно в деталях.

### 2.2. Конкретный пример победы O01 (цифры иллюстративные)

```text
┌──────────────────────────────────────────────────────┐
│ О01 · ПЕРВЫЙ КОНТАКТ                    ПОБЕДА       │
│ 700 уничтожений                  +◈ 214 КСЕНИТА     │
│                                                      │
│ ВИНТОВКА: +660 убийств · М1 → М3                     │
│ До М4 / ДВОЙНОЙ КАТУШКИ: 140 убийств                 │
│                                                      │
│ ОТКРЫТА: О02 «КЛЕЩИ ПЕРИМЕТРА»                       │
│ ЯДРО БУРИ ПОЛУЧЕНО · ЕЩЁ 2 ЗАПИСИ О ПРОГРЕССЕ       │
│                                                      │
│ [ПРОДОЛЖИТЬ → О02]         [УЛУЧШИТЬ / ПОДРОБНЕЕ]   │
└──────────────────────────────────────────────────────┘
```

**Проверка арифметики:** суммарно 700 = 660 винтовка + 40 Гравимолот. Пример состава противников 650 Бегунов + 49 Плевунов + 1 элита = 700; он живёт только в деталях. Суммарные 660 убийств винтовки при нулевом старте дают M3, так как M3 = 400, M4 = 800 (02.6 v0.2); до M4 остаётся 140. **214** — модельная награда за 700 убийств, боевой уровень 13, T1, без бонуса гнезда/утилизации; не гарантированная награда O01. `◈ 214` — доход за бой, **не весь кошелёк**.

При появлении нескольких открытий приоритет: **новая сюжетная операция/регион → одно оружейное/технологическое открытие → другие награды в раскрытии**. Не скрывать уже полученное, лишь переносить детали с первого экрана.

### 2.3. Первая победа → добровольная первая покупка

- После результатов CTA `УЛУЧШИТЬ` переносит в Развитие → Лаборатория → подборка из **двух ведущих технологий**: `Пробивной сердечник` / `Аварийный конденсатор` по **◈180** каждая (цены проектные из 02.7).
- Другие реально доступные предметы, например модули от полученного M2, **не скрыты и не блокируются**: в `Всё доступное`. Но они не конкурируют с двумя обучающими предложениями на одном маленьком экране.
- Игрок видит **назначение, цену и реальное отличие** каждого выбора: «Помогает поражать плотный строй» против «Даёт один аварийный импульс реактору»; точные характеристики из боевых документов, не придумываем их в UX.
- Одноразовый исследовательский грант **только если первый успех и текущий баланс меньше ◈180**; начисление = `180 − подтверждённый баланс`, видно в журнале наград, выдаётся ровно один раз. Если после предыдущих поражений баланс ≥180, гранта нет.
- После покупки показываем `Изготовлено · Постоянно`, итоговый баланс. Если улучшение требует выбора слота — следом предлагается `УСТАНОВИТЬ` либо поясняется автоматический постоянный эффект **только если он предусмотрен самой технологией**. Не обещаем активность эффекта до установки.
- `НЕ СЕЙЧАС · ПРОДОЛЖИТЬ К O02` доступно **всегда**, покупка не является пропуском в кампанию. Если игрок достаточно богат, обе технологии могут быть куплены позднее по общим правилам; никакого UX-ограничения «первую покупку ровно одну».

**Важная граничная ситуация:** игрок в O01 очень результативен и уже открыл M2-модуль винтовки. На итогах можно показать `Новое: M2`, но первая лабораторная витрина рекомендует пару технологий, а каталог оставляет M2-модуль доступным. Иначе интерфейс создавал бы ложное ощущение, что модуль пропал.

### 2.4. Поражение и сохранение прогресса

```text
О01 · РЕАКТОР ПОТЕРЯН
Уничтожено: 318    Получено: ◈ <подтверждённая сумма>
ПРОГРЕСС СОХРАНЁН: Винтовка +N, исследования видов +N
Новая O02 пока не открыта
[ПОВТОРИТЬ O01]  [РАЗВИТИЕ]  [ПОДРОБНЕЕ]
```

Если Гравимолот был активирован, его постоянная разблокировка сохраняется по ранее утверждённому правилу. Причина поражения выводится только из подтверждённого итогового события; не делаем ложных персонализированных советов. Если игрок проиграл до первого исследования, не рисуем фиктивного открытия.

### 2.5. Последующие результаты — контекстные

- O02: при первой победе выводится `Чертёж Вулкана`; доступ к C-A01 дополнительный, обозначить как `Открыт побочный контракт`, без обязательной переадресации.
- O03: впервые появляется чертёж Разлома, игрока ведём к O04 без требования немедленной покупки.
- O04: **«Глубины улья открыты»** важнее всего прочего, а рельсотрон и остальные награды — в компактном раскрытии.
- Повторная старая операция: вместо «открыта O02» показываем ближайший релевантный ранг или исследование, и CTA по умолчанию `ЕЩЁ РАЗ` / `ВЫБРАТЬ ОПЕРАЦИЮ` в зависимости от того, что игрок сделал ранее; не перебрасывать насильно на следующую сюжетную.

### 2.6. Промежуточное состояние сети

- Данные боя подтверждены, но награда ещё нет: показываем `Ксенит начисляется…` **только вместо суммы валюты**; не подменяем нулём. Прогресс оружия отображается, когда подтверждён.
- Если игрок возвращается в лобби до отображения всей аналитики, не блокировать его бесконечно, но **не показывать недостоверное состояние кошелька для покупки**. На экране развития — `Баланс синхронизируется` и безопасно недоступные платежные CTA до подтверждения профиля.
- При сбое начисления — явная `Проверить начисление` / `Повторить синхронизацию`, не команда повторно выдать награду и не клиентское самостоятельное списание.
- Награда, мастерство, флаги миссий должны сохраняться и корректно синхронизироваться сервером; это требование целевого UX, **не утверждение о реализованном серверном протоколе**.

## 3. В БОЙ: миссии и подтверждение высадки

### 3.1. Вид по умолчанию

```text
SWARMFALL                         ◈ Ксенит: 214
[В БОЙ]   [РАЗВИТИЕ]

СЛЕДУЮЩАЯ ОПЕРАЦИЯ
[О02 «КЛЕЩИ ПЕРИМЕТРА»] [Реакторный двор · T1]
Новая угроза: Прыгун (если уже раскрыт просмотром O02)
Задача: заряжай ретранслятор убийствами рядом с ним
Первое прохождение откроет: чертёж Вулкана

СНАРЯЖЕНИЕ: Дуговая винтовка · Базовая форма · Гравимолот
[ИЗМЕНИТЬ]                       [В БОЙ]

[ВСЕ ОПЕРАЦИИ] [ПОВТОРНЫЕ КОНТРАКТЫ]
```

**Отдельное решение REVIEW:** результат → продолжить приводит **в этот экран**, а не запускает миссию. Это даёт один чёткий момент на подтверждение экипировки и готовности. Путь отказавшегося от лаборатории игрока: **2 действия** после просмотра результатов: `Продолжить → В бой` (в соло, если сервер уже готов). Не добавлять обязательные `Получить награды → Закрыть окно → Записать в журнал → Подтвердить → Запустить`.

### 3.2. Остальной каталог операций

- O01–O04 на Реакторном дворе; O05–O06 в Глубинах улья; C-A01 «Кислотный фронт» после O02 — добровольный.
- Сюжетная O-цепочка линейная, победа открывает следующую, T1 всегда доступен для новых сюжетных этапов; высокий T не обязателен для продолжения сюжета.
- Неизвестный до знакомства враг обозначается загадочным сигналом, **не полный список будущих боссов**.
- После победы над O04 главная карточка переключается на O05 и новую карту; повтор O01–O04 не исчезает.
- При намеренном повторе предыдущей миссии путь «Результаты → Повторить» не должен автоматически отправлять игрока в самую новую O-операцию.

### 3.3. Кооператив (не выдумывать готовую архитектуру)

В существующем коде после результатов кнопка отправляет `send("continue")` и может показывать `ЖДЁМ ОТРЯД`. Это реальная текущая семантика, её нельзя незаметно заменить личным прямым запуском нового контракта. **Целевой UX:**

1. Личный результат каждого игрока имеет свои убийства, Ксенит, исследование и мастерство; коллективная победа может открыть сюжетную операцию каждому по будущему отдельно утверждаемому правилу допуска, но не копирует личные убийства других игроков.
2. `Вернуться в лобби`/`Продолжить` инициирует согласованное групповое возвращение; состояние `Ждём отряд` не следует заменять фальшивой доступностью «В бой», пока группа не вернулась в меню.
3. Посещение «Развития» в лобби **не является голосом готовности** и не может заставить остальных ждать завершения покупок без права отменить готовность.
4. Лидер выбирает контракт и угрозу, остальные видят их и нажимают `ГОТОВ`; при смене контракта или угрозы готовность сбрасывается по ясному правилу.
5. Допуск игрока к чужой ещё не открытой сюжетной O-операции не решён на 02.9; **не обещать ему сюжетное открытие и не блокировать его молча** до отдельного co-op решения.

## 4. РАЗВИТИЕ — подробные состояния

### 4.1. Арсенал

**Для любой из 4 основных пушек**: настоящая 3D-модель в роли основного визуального ориентира (из существующего `Preview.weapon`), отображаемые `M<N>/20`, суммарные убийства, только нужные в данный момент убийства по видам, ближайшая ступень M, статус `Владею / Нужен чертёж / Изготовить / Экипировано`.

- Одна текущая пушка перед запуском; форма базовая или уже изготовленная постоянная; отдельные слоты одного CORE и совместимого ADAPTER из 02.6. Профиль хранит владение, разблокировку, покупку и выбор отдельно.
- **Доступно ≠ изготовлено ≠ установлено**. Изготовленная форма/CORE не включается самостоятельно при возвращении из лаборатории, если предмет требует сознательного выбора; обратный случай только для пассивных глобальных технологий, если 02.1/02.7 так определят.
- Текущий список убийств по видам — **по оружию**, а общий счётчик вида — только в Исследованиях. Названия и числа не путать.
- Временные карточки I–III **не выставлять как узлы дерева оружия**. При желании отдельный tooltip «Как совместимо с Расщеплением» вместо фиктивного рецепта.

Эскиз детали:

```text
АРСЕНАЛ > ДУГОВАЯ ВИНТОВКА                 М7 / 20
[3D оружие / выбранная форма]    Убийств: 3 240
До M8: 560 [==================----] (M8 = 3800)
По видам: Бегун 2 840 · Плевун 270 · Прыгун 120 · Элиты 10
CORE [Двойная катушка]    ADAPTER [Выбранный]
ФОРМА [Базовая] / [Громовержец: M10, не изготовлен]
[ВЫБРАТЬ В БОЙ] [ПЕРЕЙТИ К ИЗГОТОВЛЕНИЮ] [НАЗАД К O02]
```

### 4.2. Лаборатория

**Первая страница:** `Рекомендуется` — максимум 2–3 доступных предмета с конкретной пользой. **Остальное** — в общем списке с фильтрами `Модули / Боец / Исследования / Навыки`. Пункты в списке не теряют доступности из-за того, что не рекомендованы.

Карточка предмета (всем классам одна грамматика):

```text
ДВОЙНАЯ КАТУШКА       [ОТКРЫТА] · [НЕ ИЗГОТОВЛЕНА]
Постоянный оружейный модуль: добавляет второй импульс.
Условия: M4 ✓ | исследования/чертёж (по правилам 02.6)
Цена: ◈260 | Баланс: ◈214 | Не хватает: ◈46
[ПОЛУЧИТЬ ЕЩЁ 46] [НАЗАД К ВИНТОВКЕ]
```

При появлении достаточного подтверждённого баланса основная CTA — `ИЗГОТОВИТЬ ЗА ◈260`, после серверного подтверждения — `ИЗГОТОВЛЕНО`, затем `УСТАНОВИТЬ` если требуется. Не показывать три кнопки (`Изучить / Изготовить / Установить`) одновременно, если доступно только одно действие.

**Уточнение языка статусов:**

| Статус | Визуальное поведение | Основная CTA |
|---|---|---|
| Неизвестно (спойлер) | Силуэт, неизвестный сигнал | Нет |
| Известно, но условия не выполнены | Показать конкретную цель | `Узнать условие / К испытанию` |
| Открыто, но не хватает Ксенита/компонента | Видны цена, дефицит и источник | `Где получить` |
| Открыто и хватает ресурсов | Цена и описание эффекта | `ИЗГОТОВИТЬ` |
| Изготовлено, не выбрано | Принадлежит игроку навсегда | `УСТАНОВИТЬ` (если нужен слот) |
| Установлено | Видимое выделение и слот | `СМЕНИТЬ / СНЯТЬ` (если разрешено) |
| Сетевое ожидание/ошибка | Ничего не списано клиентом окончательно | `ПОВТОРИТЬ ЗАПРОС` только безопасно |

**Изготовление ≠ выбор слота:** для эффекта пассивной общей технологии используется корректная формулировка `ДЕЙСТВУЕТ ПОСТОЯННО`; для CORE/ADAPTER — `УСТАНОВИТЬ`, если предмет изготовлен. У дорогой эволюции — ясное подтверждение одноразовой покупки и факта, что форма принадлежит игроку навсегда. Для маленьких улучшений достаточно ясной цены и визуального подтверждения; никаких обязательных трёх pop-up окон.

### 4.3. Исследования (Бестиарий)

- Видимые **только встреченные** рядовые виды; нераскрытые слоты могут быть `Неизвестная сигнатура` без конкретной цели «Убей 6000 ...».
- Карточка вида: силуэт/модель, опасность и контрмера одним предложением, `Всего побеждено: N`, `До следующего открытия: K`, одна тематическая награда, `Где встречается` только известные игроку операции.
- При разблокированном техе `ИЗГОТОВИТЬ В ЛАБОРАТОРИИ` с контекстным переходом к нужной карточке. Убийства по видам в этом разделе — **глобальные**, не привязанные к одной винтовке.
- «Носитель ядра» — сюжетная элита и трофей; не заставлять новичка считать её одиннадцатым массовым видом.

## 5. Телефон, ПК и доступность

### 5.1. Mobile-first по фактически доступной области, не только диагонали

Текущий `Menus.buildLobby` рисует базовый холст **1280×720**, `Menus.buildResults` — **1040×660**, а `showLobby`/`showResults` масштабирует его. **Этот механизм в исходниках — факт, а не готовый mobile UX.** В будущем UI использует адаптивные компоновки по измеренной безопасной области и текущему типу ввода:

- **Широкое пространство:** уместен двухколоночный экран результата/арсенала, раскрываемая правая панель. Но CTA и статус остаются в постоянных предсказуемых местах.
- **Телефон горизонтально:** одна главная зона результата, до 2 ключевых прогресс-блоков, **нижняя закреплённая CTA в пределах safe area**. Вторичные действия сворачиваются. Развитие: один предмет за раз, вкладки компактные, без боковой таблицы 4×2 мелких перков.
- **Динамически узкое окно/мультиокно:** переход к последовательности `список → деталь`, не уменьшать все элементы вдвое. Если игра допускает портрет, обеспечить реальную прокрутку и закреплённую кнопку, не обещать автоматического поворота.
- Интерактивные элементы с проектным ориентиром крупного удобного касания и расстоянием между опасными соседними действиями; проверить реальным пальцем на устройстве. Условные `44–56` не объявлять универсальной гарантией Roblox пикселей/dp.
- `ScreenGui.ScreenInsets=CoreUISafeInsets` как **направление** для важного меню, если оно совместимо с контейнерами; верхний Roblox UI, вырезы камеры и системные жесты не должны перекрывать кнопки. Фоновая графика может уходить за границы safe area, **действия — нет**.
- Текст цены/статуса и кнопки читабелен на русском без увеличения масштаба; не полагаться только на цвет (иконка + слово `Куплено / Недоступно / Выбрано`). Подпись ввода по активному устройству (мышь/тач/геймпад), упорядоченный фокус и гарантированная кнопка Назад.

**Результат на телефоне:** первая видимая зона может содержать `ПОБЕДА`, `+◈214`, `700 УБИЙСТВ`, `НОВОЕ: O02` и `ПРОДОЛЖИТЬ`. Блок подробного M-прогресса допускается ниже/в раскрытии, если реальный viewport не позволяет показать всё читабельно. **Не нарушать главное правило ради буквального следования десктопному wireframe.**

### 5.2. Критерий принятия: доступность действия прежде красоты

1. Кнопка «Продолжить» видна/доступна без обязательной прокрутки на основных поддерживаемых горизонтальных экранах; ни Roblox topbar, ни вырез её не перекрывают.
2. Из результатов до экрана выбора операции — **1 действие**, затем для сольного старта — **1 действие** (после готовности сервера и при выбранном снаряжении).
3. Для первой покупки — результат → лаборатория → выбор технологии → подтверждённое изготовление → возвращение к O02; ни один шаг не требует закрытия перекрывающихся подсказок вручную.
4. На мобиле в эволюциях не пропадают имя формы, цена, причина блокировки, CTA из-за ширины русского текста.
5. Фокус геймпада проходит по активным элементам и не уходит за край/на скрытые кнопки; на ПК работают понятные Назад/Esc.

## 6. Риски, которые REVIEW не разрешает за пользователей

1. **Точное графическое оформление**: этот документ — схема, а не утверждённый pixel-perfect референс. Нужны отдельные **игровые** макеты, основанные на фактической тёмной палитре `Theme.luau` (cyan/gold/red), шрифтах с кириллицей, моделях оружия/монстров и текущей композиции. Не подменять всё случайными sci-fi арт-изображениями.
2. **Плотность первого забега, параметры модулей и экономика**: не изменять ни одного порога/цены через UX. `214`, `700`, `180`, `M3` — иллюстрации из согласованных моделей, но не измеренные live значения.
3. **Ксенит** остаётся рабочим названием до окончательного подтверждения; менять лишь локализованный UI-текст, не legacy-сохранение `scrap`.
4. **Сюжетный доступ приглашённого игрока в коопе** не решён. Отдельная геймдизайнерская политика требуется до реализации полноценной кампании в отряде.
5. **Перезапуск из экрана результатов** зависит от текущего серверного `send("continue")`. Целевой путь `Продолжить → O02 → В бой` не является описанием уже работающего прямого роутинга; это **новое UX-требование**, требующее отдельного решения совместимости с серверной сессией.
6. **Изготовление и установка в одном действии**: допустимо лишь если объект/слот однозначен, сервер подтвердил покупку и игрок об этом видит. Иначе обязательно показывать отдельную установку; не применять изменения тихо.

## 8. Итог и границы следующего шага

**Концептуально принятая редакция 02.9:** два верхних направления `В БОЙ` / `РАЗВИТИЕ`, контекстная навигация и deeplink по предметам, один быстрый экран результата, необязательная первая лаборатория с 2 рекомендуемыми технологиями, личный прогресс от последнего убийства, честные состояния изготовленного/установленного, адаптивное mobile-first отображение, безопасный кооп-переход.

**Не принято как факт реализации:** новый UI, сохранение кнопки «Продолжить» через сетевое состояние, мобильные макеты, серверная атомарность транзакций или новые профили. В `src.7z` действуют старые меню/скрап/карточные рецепты. Новые UX-правила **предназначены для будущего отдельного задания**, после подтверждения игровых экранов.

**Следующий осмысленный этап:** `[DESIGN] PROGRESSION 02.9 — VISUAL REFS PREP` — подготовить **целевые референсы реальных экранов** Results / Operations / Development, с опорой на фактические игровые скриншоты или живой геймплей и исходный `Theme.luau`. До их утверждения **никаких поручений внедрения**.
